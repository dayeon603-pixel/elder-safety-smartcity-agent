# Security algorithms (slide-ready)

Every row states what the code does today and what it does not. Parameters are the code defaults;
env overrides are named.

| Concern | Algorithm | Parameters | Why this one | Limits (stated honestly) |
|---|---|---|---|---|
| Password storage | Argon2id (argon2-cffi) | t=3 iterations, m=64 MiB, p=4 lanes, 16-byte random salt, 32-byte tag (RFC 9106 second recommended parameter set) | Memory-hard, so GPU/ASIC cracking is expensive. The PHC string embeds parameters; a login with an outdated hash re-hashes it (`needs_rehash`). Passwords are used byte-for-byte (whitespace is not stripped); min 12 chars on registration, max 128. | No breached-password check, no password-reset or e-mail verification flow. |
| Login timing | Dummy-hash verification | one Argon2id verify for unknown emails | Wrong-password and unknown-email logins both cost one Argon2id evaluation and return the same 401. | Not constant-time end to end (DB lookup, audit write). Response-time difference was not measured. |
| Registration | Uniform reply | `POST /auth/register` always returns 202 with the same body, no token; client then calls `/auth/login` | The status code and body do not reveal whether an e-mail is already registered. The Argon2 hash is computed before the lookup on both paths. | Timing of the two paths was not measured. Login on an existing e-mail with a wrong password still returns 401, as expected. Admin accounts only come from `python -m app.cli seed-admin` or a `KCF_ADMIN_EMAIL` match at registration; the e-mail match is unverified, so seed-admin is the safe path. |
| Session token | HMAC-SHA256 signed token (stdlib `hmac`) | claims `v, sub, role, iat, exp`; TTL `KCF_TOKEN_TTL_S` (default 900 s, integer >= 1); signing secret `KCF_SECRET_KEY` | Stateless and short-lived. The MAC is checked with `hmac.compare_digest` before the payload is parsed. Base64url is decoded strictly (alphabet check plus canonical re-encode). | No revocation before expiry. The `role` claim is informational: authorisation reads the user row from the DB. The token key is the raw secret (no key separation from other uses of it). |
| Secret quality | Startup check | `KCF_SECRET_KEY` >= 32 chars, >= 10 distinct characters, no placeholder words (changeme, secret, password, example, ...) | Stops `aaaa...` and copied example values at boot. | A sanity filter, not an entropy measurement. Use `make env` (32 random bytes, hex). |
| SQL injection | Parameter binding (`?`) | every user value is a bound parameter; only constant column lists are interpolated into SQL text | The driver never parses user input as SQL. Strict pydantic models reject malformed input first. | A design rule checked by tests and review, not formally verified. |
| Abuse control | Token-bucket rate limiter | general: capacity 60, refill 20/s; `/auth/*`: capacity 10, refill 0.2/s; `/audit/*`: capacity 5, refill 0.1/s; HTTP 429 + Retry-After | Allows bursts, caps sustained rate, O(1) per request. Client key: socket peer IP, or with `KCF_TRUST_PROXY=true` the rightmost `X-Forwarded-For` entry (the one our nginx sets; left entries are client-controlled and ignored). IPv6 clients are keyed by /64. Memory is bounded (10,000 keys): only fully refilled buckets are evicted, and if none are, unseen keys share one overflow bucket, so flooding with fake keys cannot reset a throttled client. | In-memory and per process (not shared across workers or hosts). `KCF_TRUST_PROXY=true` is only safe when the backend is reachable solely through the proxy (as in docker-compose, which uses `expose`, not `ports`). Behind Docker Desktop/colima port forwarding nginx may see every client as the VM gateway address, so all clients then share one bucket. |
| Tamper evidence | HMAC-SHA256 hash chain | `hash = HMAC-SHA256(key, prev_hash \n canonical_json(ts, actor, action, detail))`, genesis `0x00..`; key = HKDF-SHA256 of `KCF_SECRET_KEY` (label `kcf/audit-chain/v1`) or `KCF_AUDIT_KEY`; the key is never stored in the DB. SQL triggers forbid UPDATE, DELETE and any INSERT that collides on id, prev_hash or hash (so `INSERT OR REPLACE` cannot overwrite); `UNIQUE(prev_hash)`; `recursive_triggers=ON`; `synchronous=FULL` | Someone who can write the database file but does not hold the key cannot recompute a valid chain. `GET /audit/verify` recomputes the chain and returns the head hash to pin outside the database. | Anyone holding the key can forge entries. Deleting the tail, or restoring an older copy of the database, is only detectable against a head you pinned earlier. Verification is rate limited and cached for 5 s (`KCF_AUDIT_VERIFY_TTL_S`), so a fresh tamper can take up to 5 s to show. Failed logins write at most one audit row per client per minute (counts of the rest are reported on the next row; the counter lives in process memory). The pre-upgrade unkeyed chain is kept read-only as `audit_log_legacy_v1`. |
| Transport hardening | Response headers | `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-site`, `Cache-Control: no-store`; `Strict-Transport-Security: max-age=31536000` only when `KCF_HSTS=true`. Set on every response, including 4xx, 429 and 500. | Limits what a browser will do with an API response if it is ever rendered: no framing, no sniffing, no script. | The app speaks plain HTTP; TLS must be terminated in front of it, and HSTS should only be switched on once that is true. The frontend's nginx sends its own CSP for the pages it serves. |
| Error handling | Sanitised errors | 422 bodies contain only `loc, msg, type` (the submitted `input` and `ctx` are removed); unhandled exceptions return `{"detail":"internal server error"}`, details only in server logs; OpenAPI schema is served only with `KCF_ENV=dev` | Request values (e.g. a rejected password) are never echoed, and stack traces never reach clients. | Messages still name the failing field and, for CSV ingest, the row number. |
| Cross-origin | CORS allowlist | explicit origins from `KCF_CORS_ORIGINS`; wildcard refused at startup; methods GET and POST; credentials off | Only listed origins may call the API from a browser. | CORS is a browser rule; it does not stop non-browser clients. |
| Dataset provenance | SHA-256 of file bytes, column roles | `sha256` is computed by the server over the exact bytes it parsed (a mismatch with the pre-read hash aborts the ingest); `fetched_at` = ingest time; `file_mtime` stored separately; the id/time/label/group columns and the feature list are stored with the dataset and the label can never be loaded as a feature | Any result is traceable to the exact bytes it was computed on. Streamed ingest keeps a dataset invisible (`status=loading`) until every row is stored. | `source_url` and `license` are declared by the user and not verified. Timestamps without a zone are taken as UTC. The WDBC example hashes the sklearn-bundled arrays, not a UCI file (stated in its description). |
| Demo access | Shared demo token | `KCF_DEMO_TOKEN` (>= 16 chars) checked with `hmac.compare_digest` on every `/agent/*` and `/sim/*` request, header `X-Demo-Token`; the agent forwards it on its own simulator calls | Keeps the action endpoints and the simulator inboxes off the open network during the demo without a login flow. | One shared secret, no per-user identity or expiry; unset = open (logged at startup). |
| Agent self-calls | Loopback-only base URL | `KCF_AGENT_SELF_URL` must be `http://127.0.0.1\|localhost:<port>` (validated at startup); default `http://127.0.0.1:<port the socket was accepted on>`; the request's Host header is never used | A client cannot make the agent fetch "tool results" from a host of its choosing (SSRF) and pass them through grounding. | The simulators are still this same process; no network isolation beyond loopback. |
| Agent run bounds | Monotonic budget + semaphore + body caps | `KCF_AGENT_RUN_BUDGET_S` 40 s; each Ollama call `min(30 s, remaining)`, connect 2 s; after one LLM failure no further LLM call in the run; at most `KCF_AGENT_MAX_CONCURRENT` (3) runs, others 503 + Retry-After; bodies: `/sim/*` 64 KB, `/agent/run` 6 MB, JSON depth <= 32; rate limits `/agent/run` 6 burst / 0.5 per s, `/sim/*` 30 burst / 2 per s | A stalled or slow model, a huge snapshot, or a burst of runs can never hang the server or fill the append-only inbox unboundedly. | The semaphore and limiters are per process (single worker in `make demo`). |
| LLM output guard | Schema-constrained plan + numeric grounding | Ollama `format` JSON schema (tool enum per trigger), server-side JSON-schema subset check, context binding of every location/measurement field, server-issued bundle ids; briefing numbers must match tool-result numbers (rounding; `%` only from a fraction, `만` only from a count; coordinates, latencies and ids are not evidence; `119`/`CAP 1.2` literals matched with digit boundaries); banned terms (diagnoses, `None`, conformance claims); template fallback | The model proposes; it cannot redirect an alert, invent a measurement or launder a fabricated figure. | Grounding checks numbers and a few words, not meaning. The RSU driver text is a fixed template, never model text. |
| Input validation | pydantic v2 strict models, CSV rules | `extra="forbid"`, strict types, length and pattern limits; CSV caps `KCF_MAX_CSV_BYTES` (50 MiB) and `KCF_MAX_CSV_ROWS` (500,000); filename allowlist and resolution inside the data directory (symlink escape blocked); labels must be integers from an allowed set; short or long rows, empty or duplicate headers, bad timestamps and empty files are rejected with the row number | Rejects unknown fields, path traversal and malformed data at the boundary. | `/datasets/ingest` reads only files already placed in the data directory. |
